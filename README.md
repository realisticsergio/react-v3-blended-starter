ПОСТИ: ПОШУК, СТВОРЕННЯ, РЕДАГУВАННЯ



Реалізуйте застосунок для роботи з постами: перегляд, створення, редагування, пошук та пагінація. Для роботи використовуйте публічний REST API JSONPlaceholder. Дані надсилаються та отримуються за допомогою axios. У застосунку мають бути реалізовані форми створення/редагування, список постів, модальне вікно, пошук.



Прев'ю робочого застосунку:




Загальна інформація

Проєкт вже містить готову структуру та стилізовані компоненти.
Компоненти, що беруть участь:
<App>, <CreatePostForm>, <EditPostForm>, <PostList>, <Pagination>, <Modal>, <SearchBox>.
Дані отримуються через функції в src/services/postService.ts.
API: https://jsonplaceholder.typicode.com/posts
Типи даних винесено у src/types/post.ts.
Типізація пропсів компонентів через interface.
Усі функції, колбеки та обробники подій типізовані.
Для HTTP-запитів використовується axios.


Опис роботи з API

GET /posts — отримання списку постів (усі пости). Підтримує query-параметри для фільтрації та пагінації:
q — пошуковий запит (фільтрація по заголовку та тілу поста);
_page — номер сторінки (для пагінації);
_limit — кількість постів на сторінці (для пагінації).
POST /posts — створення нового поста
DELETE /posts/:id — видалення поста
PATCH /posts/:id — редагування поста (опціонально)
API не зберігає дані насправді, але відповідає як реальний бекенд. Тому після створення, видалення, редагування ви не помітитее оновлення в інтерфейсі, але у вкладці розробника в браузері ви побачите коректну відповідь.


Контейнер додатка (App.tsx)

Компонент App виконує наступні функції:



1. Встановлює початкові стани:

активна сторінка (currentPage);
відкриття модального вікна (isModalOpen);
стан створення (isCreatePost) та редагування (isEditPost) поста;
пост, який редагується (editedPost);
пошуковий запит (searchQuery) із debounce.
2. Використовує React Query для отримання постів з бекенда:

передає debouncedSearchQuery та currentPage як залежності;
використовує keepPreviousData для збереження попередніх результатів при зміні сторінки;
обчислює кількість сторінок (totalPages) та отримує масив posts.
3. Рендерить:

SearchBox з функцією пошуку;
Pagination, якщо більше однієї сторінки;
Кнопку "Create post", яка відкриває модальне вікно із формою створення;
Модальне вікно, в якому відображається або CreatePostForm, або EditPostForm;
PostList, передаючи туди функції відкриття модального вікна і редагування.


Поведінка модального вікна

Модальне вікно відкривається по натисканню на кнопку Create post, або при виборі поста для редагування у PostList. При закритті модального вікна форми очищуються автоматично.

Редагування поста можливе лише після вибору конкретного поста – його об'єкт передається до стану editedPost.



Пошук

Поле пошуку (SearchBox) оновлює searchQuery, яке передається в бекенд. Пошук виконується з затримкою 300 мс (debounce). При зміні запиту сторінка скидається на першу.



Пагінація

Компонент Pagination з’являється лише якщо кількість сторінок > 1. Він оновлює currentPage, що тригерить оновлення запиту на бекенд.



Компонент PostList

Цей компонент відповідає за відображення списку постів у вигляді елементів списку з можливістю редагування та видалення кожного з них. Він приймає три пропси:

posts — масив постів, кожен з яких має структуру з полями id, title і body.
toggleModal — функція, яка відкриває модальне вікно для редагування.
toggleEditPost — функція, яка приймає об'єкт поста та передає його, до App.


Коли користувач натискає кнопку "Delete", відповідний пост видаляється. Після успішного видалення викликається queryClient.invalidateQueries, щоб оновити список постів у кеші, і виводиться повідомлення про успішне видалення через alert().

Кнопка "Edit" викликає дві функції:

toggleModal() — відкриває модальне вікно з формою редагування.
toggleEditPost(post) — передає вибраний пост у форму для редагування, щоб попередньо заповнити поля.
Кожен пост виводиться у вигляді елементу списку з заголовком (title), вмістом (body) та кнопками для редагування і видалення.





Компонент Pagination (ReactPaginate)

Цей компонент відповідає за навігацію між сторінками. Використовується готовий пакет react-paginate, який дозволяє швидко реалізувати клікабельну пагінацію з кастомним виглядом.

Використовуйте для компонента бібліотеки ReactPaginate наступні пропси:

<ReactPaginate
  pageCount={totalPages} // скільки сторінок показати
  pageRangeDisplayed={5} // скільки номерів показувати всередині пагінації
  marginPagesDisplayed={1} // скільки показувати по краях (перед трьома крапками)
  onPageChange={({ selected }) => onPageChange(selected + 1)} // react-paginate починає з 0
  forcePage={currentPage - 1} // для синхронізації зовнішнього currentPage з внутрішнім станом
  containerClassName={css.pagination} // клас контейнера (ul)
  activeClassName={css.active} // активна сторінка
  nextLabel="→" // мітка кнопки "вперед"
  previousLabel="←" // мітка кнопки "назад"
/>



Компонент SearchBox

Цей компонент відповідає за отримання пошукового значення з інпуту та передачі його до App. Він приймає два пропси:

value— рядок пошукового запиту (контрольований елемент).
onSearch— функція, яка приймає введене значення та передає його до App.


Компонент модального вікна (Modal)

Цей компонент відповідає за відображення модального вікна з затемненим фоном та підтримкою закриття через Escape або клік по фону.

Modal використовується як оболонка для інших компонентів, наприклад, CreatePostForm або EditPostForm, які передаються в children. Має бути реалізована через createPortal().

Пропси:

onClose: () => void — функція, яка викликається для закриття модального вікна.
children: React.ReactNode — вміст модального вікна (форма або будь-який інший JSX).
Основні можливості:

1. Закриття через клавішу Escape.

Обробник keydown додається при монтуванні та прибирається при демонтуванні.
Якщо користувач натискає Esc, модальне вікно закривається (onClose()).
2. Заблокований скрол сторінки.

При відкритті модалки document.body.style.overflow = "hidden".
При закритті — скрол повертається (overflow = "").
3. Закриття по кліку на фон (бекдроп).

Якщо клік був по самому фону (e.target === e.currentTarget), викликається onClose().


Форма створення поста

Компонент CreatePostForm відповідає за створення нового поста в системі. Він відкривається у модальному вікні після натискання кнопки Create post.

Форма містить два поля:

Title – заголовок поста (обов’язковий, мінімум 3 символи, максимум 50);
Content – текст поста (обов’язковий, максимум 500 символів).
Для валідації полів використовується бібліотека Yup. У разі помилки під відповідним полем з'являється повідомлення про помилку.



Після натискання на кнопку Create post:

1. Дані надсилаються до бекенду за допомогою функції createPost, яка вже оголошена в postService.ts.

2. У разі успішного запиту:

Кеш постів оновлюється через queryClient.invalidateQueries(["posts"]);
З'являється alert з повідомленням Post created successfully!;
Форма закривається викликом функції onClose().
3. Форма очищається автоматично після успішної відправки.

Кнопка відправки (Create post) блокується, поки триває запит (mutation.isPending).
Кнопка Cancel закриває форму без відправки даних.



Форма редагування поста (опціонально)*

Компонент EditPostForm відповідає за оновлення наявного поста. Він відкривається у модальному вікні після натискання кнопки Edit post.

Форма заповнюється поточними даними поста (initialValues), які передаються через пропси:

{ id: number; title: string; body: string }.

Поля форми:

Title – заголовок поста (обов’язковий, мінімум 3 символи, максимум 50);
Content – текст поста (обов’язковий, максимум 500 символів).
Валідація:

Валідація полів відбувається за допомогою Yup.
У разі помилки відображається відповідне повідомлення біля поля.
Після натискання на кнопку Edit post:

Дані надсилаються до бекенду через функцію editPost, яка вже оголошена в postService.ts.
Після успішної відповіді:
Кеш постів оновлюється через queryClient.invalidateQueries(["posts"]);
З'являється alert з повідомленням Post edited successfully!;
Форма закривається викликом onClose().
Кнопка Edit post блокується під час запиту (mutation.isPending).
Кнопка Cancel закриває форму без збереження змін.
